# 개발 스택 제안 — 학업나침반

> 2026-09-20 · **제안서다. 확정이 아니다.** 개발 3인이 읽고 합의한 뒤에 시작한다.
> 여기 적힌 건 아무것도 구현돼 있지 않다.

## 전제 — 이미 돌아가고 있는 것

입력 쪽은 **Next.js(App Router) + TypeScript + Supabase + Vercel** 로 이미 배포돼 있다.
출력 쪽(진단·로드맵)도 **같은 레포·같은 스택**으로 가는 것을 기본안으로 한다.

새 스택을 얹자는 제안은 "이걸로 안 되는 이유"를 먼저 말해야 한다. 학기 안에 끝내야 하고,
배포 경로가 둘이 되면 그때부터 시간은 기능이 아니라 연결에 쓰인다.

## 파트별 제안

### 💻 개발-A · 데이터 · API

| | 제안 | 이유 |
|---|---|---|
| API | **Next.js Route Handler** (`app/api/*/route.ts`) | `api/reports` 가 이미 이 패턴. 별도 서버 불필요 |
| DB 접근 | 지금은 `fetch` + PostgREST. **조회가 3개 넘어가면 `@supabase/supabase-js` 도입 검토** | 지금 방식도 충분하다. 쿼리 조립이 지저분해지는 시점이 갈아탈 시점 |
| 캐싱 | 집계 조회에 `next: { revalidate: 60 }` | `v_week_load` 는 초 단위로 바뀌지 않는다 |
| 키 관리 | **anon key 는 서버에만.** 브라우저가 Supabase 를 직접 치지 않는다 | 지금 규칙 유지 |

**만들 것** `GET /api/load` · `GET /api/courses` · `GET /api/tracks` · `POST /api/diagnose`

### 💻 개발-B · 진단 화면

| | 제안 | 이유 |
|---|---|---|
| UI | **React + 순수 CSS** (`globals.css` 확장) | 입력 폼이 이 방식. Tailwind 를 중간에 얹으면 화면 둘이 따로 논다 |
| 차트 | **처음엔 CSS 막대그래프.** 부족하면 그때 Recharts | 16주 막대는 `div` 높이로 충분하다. 클릭 상세·툴팁은 어차피 직접 만든다 |
| 상태 | `useState` + URL 쿼리스트링 | Zustand·Redux 쓸 규모가 아니다. URL 에 담으면 조합 공유가 공짜 |
| 반응형 | 모바일 우선 | QR·링크로 들어온다. 대부분 폰이다 |

> **URL 에 조합을 담자**는 게 이 파트의 핵심 제안이다.
> `?courses=12,34,56` 이면 "내 시간표 봐줘" 를 링크 하나로 공유할 수 있다.
> MZ 공유 재미(캐릭터 반응)도 이 위에서 돈다.

### 💻 개발-C · 알고리즘

| | 제안 | 이유 |
|---|---|---|
| 언어 | **TypeScript.** Python 분리 반대 | 배포 경로가 하나 더 생긴다. 조합 탐색은 TS 로 충분히 빠르다 |
| 위치 | `lib/score.ts` · `lib/conflict.ts` · `lib/roadmap.ts` | DB·React 를 모르는 **순수 함수**로. 입력·출력만 있으면 테스트가 쉽다 |
| 테스트 | **여기만 테스트를 쓴다.** Vitest 권장 | 화면은 눈으로 보면 되지만 점수·충돌 규칙은 눈으로 못 본다 |

**만들 것** 부담 점수 `0.5×평균 + 0.5×상위3주 평균` · 충돌 규칙 R1~R5 ·
조합 탐색(필수 과목 고정) · 로드맵(트랙 점수 + 선수과목 위상정렬)

## 셋이 한 레포를 쓰는 방법

**파일 경계로 충돌을 막는다.** 같은 파일을 둘이 건드리지 않게 미리 나눈다.

```
A  app/api/**            lib/db.ts
B  app/diagnose/**       components/**
C  lib/score.ts  lib/conflict.ts  lib/roadmap.ts
공통  lib/types.ts       ← 여기만 셋이 합의하고 고친다
```

| | 제안 |
|---|---|
| 브랜치 | `feat/<파트>-<내용>` → PR → 1명 리뷰 → main. **main 직접 push 금지** |
| 미리보기 | Vercel 이 PR 마다 미리보기 URL 을 자동 생성한다. 디자인·기획이 배포 기다릴 필요 없다 |
| 타입 | `lib/types.ts` 를 먼저 합의한다. 여기가 흔들리면 셋 다 멈춘다 |
| AI 도구 | 자유롭게 쓰되 **PR 리뷰는 그대로.** `lib/` 알고리즘은 테스트로 확인 |

## 안 하기를 권하는 것

| | 왜 |
|---|---|
| 별도 백엔드 (Express · FastAPI) | Vercel 함수로 충분하다. 서버 하나 더 = 배포·환경변수·CORS 가 하나 더 |
| ORM (Prisma · Drizzle) | 스키마가 이미 SQL 로 있고 읽기 위주다. 마이그레이션 도구가 둘이 되면 꼬인다 |
| 상태관리 라이브러리 | 화면 3개짜리 서비스다 |
| 로그인·인증 | **"개인정보 0" 이 설계 원칙이자 발표 방어 축이다.** 넣으면 원칙이 깨진다 |
| 모노레포 · 마이크로서비스 | 8주 프로젝트다 |

## 먼저 정할 것 3가지

1. **`lib/types.ts` 를 누가 언제 쓰나** — 셋의 작업이 여기서 만난다. 1주차에 같이 정하는 걸 권한다
2. **진단 화면 URL 구조** — `?courses=12,34` 로 갈지. B 파트 시작 전에 정해야 한다
3. **테스트를 어디까지 쓸지** — 알고리즘만인지, API 까지인지

## 데이터를 기다리지 않는다

W1~W2 는 **더미 과목 10개를 하드코딩**해 API·화면·알고리즘을 먼저 만든다.
마스터와 응답이 차면 데이터 출처만 바꾼다. 수집과 개발은 병렬이다.
