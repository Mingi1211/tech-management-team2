# 학업나침반 — 광운대 기술과경영 2조

수강 조합의 **학기 부담을 주차 단위로 진단**하고, **관심분야에 맞는 학기별 수강 로드맵**을
제시하는 웹 서비스. 링크·QR로 접속하며 로그인과 개인정보 수집이 없다.

- 대상 학부 — 로봇학부 · 소프트웨어학부 · 정보융합학부
- 팀 구성 — 8명 (PM 1 · 개발 3 · DB 2 · 디자인/기획 2)

---

## 왜 만드는가

수강신청 도구는 **요일·시간이 겹치지 않는 조합**까지만 알려준다. 그러나 한 학기의 결과를
좌우하는 것은 시간표가 아니라 **과목 조합이 학기 중 언제 부담을 만드는가**이다.
시험기간에 팀 프로젝트 마감이 겹치는지, 매주 과제가 있는 과목을 몇 개나 담았는지는
지금 아무도 알려주지 않는다.

실제 수강한 선배들이 남긴 정량 데이터를 근거로 그 부담을 **개강 전에** 계산해 보여주고,
부담을 낮춘 대안 조합까지 제시한다.

## 설계 원칙

| | |
|---|---|
| **횟수가 아니라 시점** | 모든 부담을 주차(1~16) 단위 이벤트로 정규화해 저장한다. "과제 10회"로는 충돌을 계산할 수 없다 |
| **권한·개인정보 0** | 학교 시스템에 접근하지 않는다. 선배의 자발적 입력과 공개 교과과정표만 쓴다 |
| **`과목 × 교수 × 학기`** | 담당 교수가 바뀌면 운영이 달라지므로 개설 회차를 기본 단위로 삼는다 |
| **모르면 모른다고 표시** | 응답 수에 따라 신뢰도 A/B/C를 화면에 그대로 노출한다 |
| **교수 평가는 하지 않는다** | 과목의 운영 방식만 다룬다. 개인에 대한 점수·순위는 기능에서 제외 |

## 일정의 핵심

**입력 폼을 진단 기능보다 먼저 배포한다 (W4).**
모든 기능이 선배 데이터에 의존하는데, 개발을 끝내고 수집을 시작하면 학기가 끝난다.
수집 기간 7주 이상 확보가 목표다. 공개 전에 팀원이 먼저 채워 빈 서비스를 피한다.
