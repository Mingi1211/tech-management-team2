# db — Supabase 스키마

## 적용 방법 (1회)

1. <https://supabase.com> 에서 프로젝트 생성 (무료 티어)
2. 대시보드 → **SQL Editor** → `schema.sql` 전체를 붙여넣고 **Run**
3. **Table Editor** 에서 테이블 7개가 생겼는지 확인

다시 만들려면 `schema.sql` 맨 아래 "초기화" 블록의 주석을 풀어 먼저 실행한다.

## 테이블은 두 종류

| | 테이블 | 채우는 방법 |
|---|---|---|
| **참조** | `department` `course` `prerequisite` `track` `track_course` | 교과과정표를 보고 **우리가 CSV import** |
| **수집** | `report` `load_event` | 선배가 폼에서 제출 → **자동으로 쌓임.** 손으로 넣지 않는다 |

`department` 3건과 로봇학부 트랙 4건은 스키마 실행 시 함께 들어간다.

## 핵심 — `load_event` 는 손대지 않는다

`report` 가 한 줄 들어오면 트리거가 **주차 단위로 펼쳐** `load_event` 를 자동 생성한다.
`"mid"` → 8주차, `"final"` → 15주차로 바꾸고, `"unknown"` 은 이벤트를 만들지 않는다.

```
report 1건                          →   load_event 5건
  프로젝트 15주차                        15 project_due
  퀴즈 2회 (5주차, 12주차)                 5 quiz · 12 quiz
  중간 1회 · 기말 1회                      8 exam · 15 exam
```

CSV import 로 `report` 를 밀어넣어도 트리거가 똑같이 돈다. 그래서 아티팩트 프로토타입
데이터를 옮길 때 `report` 만 넣으면 `load_event` 는 알아서 생긴다.

## 권한 (RLS) — 끄지 말 것

Supabase 는 `anon key` 를 브라우저에 노출한 채 동작한다. RLS 를 끄면 그 키만으로
누구나 전체 테이블을 읽고 고칠 수 있다.

| 대상 | anon (브라우저) | 팀 (Studio · DBeaver) |
|---|---|---|
| `report` | **넣기만 가능.** 읽기 불가 | 전부 |
| `load_event` | 접근 불가 | 전부 |
| 참조 테이블 | 읽기만 | 전부 |
| `v_week_load` `v_course_confidence` | 읽기 가능 (집계만 공개) | 전부 |

`service_role key` 는 **절대** 레포·단톡방·클라이언트 코드에 올리지 않는다.

## 검증 결과 (2026-09-18)

PostgreSQL 16 에서 실제로 실행해 확인했다.

- 스키마 전체 실행 성공 (Supabase 롤 `anon` · `authenticated` 생성 후)
- `mid` → 8주차, `final` → 15주차 변환 확인
- `unknown` 은 이벤트를 만들지 않음 (퀴즈 3회 중 2건만 생성)
- `exam_final = 2` → 15주차 exam 2건 (코딩테스트 + 필기 분리 케이스)
- 집계 뷰 `load_score` 계산 확인 — 15주차 5.50 = exam 3.0 + project_due 2.5

## 시드 파일

**실행 순서**는 이렇다. 전부 **여러 번 돌려도 안전하다.**

```
schema.sql
  → seed-robot-courses.sql
  → seed-infoconv-courses.sql
  → seed-software-courses.sql
  → seed-lab-reports.sql
  → seed-tracks.sql
```

| 파일 | 내용 | 상태 |
|---|---|---|
| `seed-robot-courses.sql` | 로봇학부 **34과목** (1학기 17 · 2학기 17) | 완료 |
| `seed-infoconv-courses.sql` | 정보융합학부 **31과목** (1학기 16 · 2학기 15) | 완료 |
| `seed-software-courses.sql` | 소프트웨어학부 **36과목** (1학기 20 · 2학기 16) | 완료 |
| `seed-lab-reports.sql` | 로봇학실험/AI로봇실험 1~4 부담 데이터 — 폼 없이 직접 | 완료 |
| `seed-tracks.sql` | 관심분야 **12트랙 · 93건 매핑** | **[초안]** 검토 필요 |
| `check-reports.sql` | **0번** 안 채운 과목 찾기 · **1~4번** 잘못 들어온 응답 찾기 | 주 1회 |

**3개 학부 101과목.**

> 세 학부 화면 모두 **전공선택만** 잡혔다. 전공필수는 목록 윗부분이 잘려 있었다.
> 로봇학부는 그중 일부(로봇운동학·AI로봇실험3·로봇학실험)를 따로 확인해 넣었다.
> 나머지 학부의 전공필수는 아직 비어 있다.

### 분반은 행을 만들지 않는다

과목명이 같고 담당 교수도 같으면 **운영 방식이 같은 한 과목**이다. 컴퓨터구조 `-01`·`-02`
둘 다 이윤구면 한 줄이다. 분반마다 교수가 다르면 이름을 `professors` 배열에 모두 넣는다.

```
자료구조  →  professors = {박병준, 김용혁, 이영준}
```

부담이 교수마다 다른 건 선배 응답이 갈라 준다 — `report.course_key` 에 교수가 들어가서
집계 뷰가 개설분별로 나뉜다. 마스터는 "누가 가르칠 수 있는 과목인가"만 알면 된다.

### `course` 가 답하는 것

① 이 과목이 **몇 학년 몇 학기**에 열리나 ② **담당 교수**가 누구인가. 이 둘이 로드맵과
W3 선택지의 재료다. 학수번호(`code`)는 참고용이고, 두 번째 자리에서 `typical_year` 를 얻었다.

- **`name` 과 `professors` 가 정본이다.** W3 부터 폼의 과목·교수 선택지가 이 값을
  그대로 보여준다. `자동제어1` 을 `자동제어I` 로 바꾸면 선배가 고를 이름 자체가 바뀐다
- **`professors` 는 배열이다.** 분반이 여럿이면 여럿 넣는다 (로봇학실험3 = 3명)
- **교수 연락처는 레포에 올리지 않는다.** 이름만 넣는다

### 로봇학실험 / AI로봇실험

두 과목은 사실상 같은 과목이라 **`로봇학실험/AI로봇실험1~4` 한 줄로 합쳐 두었다.**
이미 옛 이름으로 돌려 둔 DB 는 `seed-robot-courses.sql` 맨 위 정리 블록이 알아서 바꾼다 —
과목 이름도, 그 이름으로 들어온 응답도 함께 고치고, 합쳐지는 과목을 가리키던 `course_id`
도 옮긴다. reset 은 필요 없다.

#### 왜 폼을 안 쓰나

전공필수라 전원이 듣고, 네 과목 모두 운영이 같고 분반이 달라도 같다 — 15주차 **팀**
프로젝트(기말 대체) · 중간 필기 1회 · 과제는 시험 주차 뺀 매주 · 퀴즈 없음. 선배 응답을
기다릴 이유가 없고, 폼으로 받으면 분반 수만큼 같은 내용이 중복으로 쌓인다.
`source = 'seed'` 로 들어가 있고 `course_id` 까지 연결돼 있다.

한 과목당 **부담 이벤트 14건** (과제 12 · 중간 1 · 프로젝트 1) 이 트리거로 생긴다.

배치는 **1 = 2-1, 2 = 2-2, 3 = 3-1, 4 = 3-2**. 3학점 4시간.

이 네 과목만 `code` 와 `professors` 가 비어 있는데 **채워야 할 빈칸이 아니다.**
전 분반 운영이 같아 교수로 갈리지 않는다. 확인 쿼리 3번도 이 넷을 제외하고 센다.
